# Security Policy

## Supported Versions

We actively release security updates and patches for the following versions of **Bigest-Mall**:

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

We take the security of **Bigest-Mall** seriously. If you believe you have found a security vulnerability or bug in our application, please do **NOT** open a public issue on GitHub.

Instead, please report it responsibly using one of the following methods:

1. **Email:** Send details to `habibullah.shahin19970@gmail.com.com` *(আপনার ইমেইল দিন)*
2. **GitHub Private Advisory:** Use the "Report a vulnerability" button under the **Security** tab of this repository.

### What to include in your report:
- A description of the vulnerability and its potential impact.
- Clear step-by-step instructions or proof-of-concept (PoC) code to reproduce the issue.
- Your contact information for follow-up questions.

---

## Response & Disclosure Policy

- **Acknowledgment:** We will acknowledge receipt of your vulnerability report within **48 hours**.
- **Fixing:** We aim to release a patch or mitigation within **7 to 14 business days**, depending on the severity of the issue.
- **Disclosure:** We ask that you give us adequate time to address the vulnerability before making any public disclosure.

---

## Preferred Security Practices for Users

To keep your deployment of Bigest-Mall secure:
- Always run the latest code from the `main` branch.
- Never commit private API keys, payment secrets, or database passwords to public Git repositories.
- Use HTTPS for all web traffic in production.

Thank you for helping keep Bigest-Mall safe and secure!
